# 怎麼寫一個新病例

內容分三層：

- **共用的骨架**（`skeleton.ts`）：開場三件事、個人與過去病史八題、系統回顧四題、身體評估十項（整體加五個模組）。每個主訴都用同一套，玩家每一關練的是同一個流程。
- **主訴模組**（例如 `chest-pain.ts`）：症影、四個真身、主訴那一段（OLD CARTS 十題）的問法、檢查項目。一個主訴寫一次。
- **病例**（例如 `c01a.ts`）：只寫這位病人的部分。

同一個主訴的每個病例，畫面上的選項一模一樣，玩家沒辦法從「有哪些題目」猜出答案。

流程固定是 **問診 → 評估 → 診斷 → 檢查**。骨架的順序參考臨床老師的 OSCE 教案，文字是重寫的。

## 從教案開始（有教案的話）

```bash
python3 tools/convert_script.py 教案.docx --id c02a
```

它會讀教案的四段（開場、OLD CARTS、個人與過去病史、身體評估），把每個問句對到遊戲的題目、把「舉牌」的異常發現對到評估項目，寫出 `drafts/c02a.draft.ts`。只想看對得上多少，加 `--report`；一次轉整個資料夾，把檔名換成資料夾。

底稿拿到之後，還有三件事要人來做：

1. **重寫。** 底稿裡病人的回答和評估結果是教案的原文。教案是別的老師的著作：只參考結構，每一句都要用自己的話重寫，病人也要重新設計。原文不進遊戲，也不進版本控制（`drafts/` 已經排除；教案裡扮演專師的人名，轉換的時候就拿掉了）。
2. **補推理。** 每條線索指向哪個真身（`tell`、`why`）、真身和要排除的、安全行動、問題摘要、回報和說明的選項、岑禾和醫師的話、文獻。底稿裡都標了 `TODO`。
3. **搬進來檢查。** 補完之後搬到 `src/data/`，照下面的步驟登記，跑 `npm run cases`。還有 `TODO` 沒補完，檢查器不會放行。

教案沒有的題目（例如「擔心什麼」），底稿會標出來要自己寫。對不上的問句列在底稿最後面，通常是那個主訴特有的追問，看要併到哪一題。

## 加一位病人（主訴已經有了）

1. 複製同一個主訴裡最像的病例檔（或是用上面的底稿），改檔名和 `id`。
2. 改這幾塊：

| 欄位 | 寫什麼 |
|---|---|
| `patient`、`reading` | 病人是誰、閱題卡上的三行字 |
| `scene` | 在哪裡：不寫是公會的病室，`ward-rain` 下雨天的病室，`dock` 碼頭的貨棧（出診） |
| `vitals` | 生命徵象。會變差的病人另外寫 `worse` |
| `answers` | 每一題這位病人怎麼回答（25 題）。**每一題都要寫**，少一題會直接報錯 |
| `findings` | 每一項評估看到、聽到、摸到什麼（10 項） |
| `results` | 每一項檢查的結果；這一關等不到的寫 `pending` |
| `answer` | `truth` 是真身；`exclude` 是還要排除的真身和分數 |
| `summaries`、`sbar`、`explain` | 問題摘要、回報、說明的選項 |
| `timeline`、`safety` | 劇本的時間點、這一關的安全行動 |
| `lines` | 岑禾、沈渡和病人在固定時刻說的話 |
| `debrief` | 其他也可以的做法、重點、文獻 |

3. 在 `index.ts` 的 `CASES` 加一行；在 `src/ui/progress.ts` 的 `QUESTS` 加一行（`needs` 寫要先完成哪一張）。病人會自動出現在圖鑑的「人物」那一頁；想加一行結案之後的事，寫在 `peopleOf` 的 `after` 裡。
4. 新的病人要有樣子：`patient.look` 對到 `src/art/ward.js` 裡的一種外表。還沒畫的，先借用現有的。
5. 跑檢查：

```bash
npm run cases
```

## 線索

回答、評估結果、檢查結果後面都可以掛一條線索：

```ts
'q-surgery': { say: '沒開過刀，也沒有躺著不動。', clue: {
  text: '沒有手術、外傷或久臥不動',     // 顯示在畫面上的短句
  kind: 'neg',                          // pos 有的、neg 沒有的、info 背景
  tell: { form: 'vascular', dir: -1 },  // 讓「血管急症」比較不像（1 是更像）
  why: '剛開刀、久臥不動，是肺栓塞常見的背景。沒有，就少一個理由。',
} },
```

- 有寫 `tell` 的線索，玩家拿到之後要自己選它指向哪一個真身。`why` 是岑禾的回應，答對答錯都會說。
- 一條線索如果有兩種合理的解讀，把另一種寫在 `alsoOk`。方向要和主要的解讀一樣：畫面只會問一個方向（更像，或比較不像）。
- 一個病例大約放 8 到 10 條要解讀的線索，問診、評估、檢查都要有。太多會拖慢節奏。
- 線索的代號不用自己取：問題 `q-surgery` 的線索就是 `c-surgery`。

## 時間和安全行動

時間點都從「下了診斷」那一刻算起，所以照順序把問診和評估做完整，不會被罰。

```ts
timeline: { worsenAfter: 120, stepInAfter: 300, doctorDelay: 90 },
```

下了診斷之後 120 秒沒有人知道，病人變差；300 秒還沒有，岑禾接手。穩定的病人只寫 `doctorDelay`。

每個病例自己宣告哪些事一定要做到。分數加起來要是 9 分。

| 類型 | 意思 | 例子 |
|---|---|---|
| `call` | 病況變差之前通報 | 林秋、阮舟 |
| `order` | 下診斷之後幾秒之內提出某項檢查 | 林秋的心電圖、莫桐的胸部 X 光 |
| `exclude` | 每個危險的真身，都要有一條讓它比較不像的線索 | 簡晴、莫桐 |
| `explain` | 說明裡一定要有的那一句 | 交代什麼情況要馬上回來 |
| `calm` | 病人穩定，不需要敲值班鐘 | 簡晴、莫桐 |

## 檢查器會擋什麼

- 少寫一題的回答、指到不存在的線索或真身、線索沒有任何行動拿得到。
- 要玩家解讀的線索沒有寫 `why`。
- 真身不是四個、沒有任何線索支持真身、要解讀的線索不夠拿滿分。
- 要求排除某個真身，卻沒有任何線索能讓它比較不像。
- 安全行動的分數不是 9 分、指到不存在的檢查。
- 問題庫少了一段（開場、主訴、病史、系統回顧）。
- 教學重點指到不存在的文獻、DOI 格式不對。
- 還有 `TODO` 沒補完。
- **照理想的打法玩不到安全達成和九十分**：表示病例裡有玩家做不到的要求。

## 加一隻症影（新的主訴）

寫一個主訴模組，照 `chest-pain.ts` 的樣子：四個真身（至少一個不危險的）、OLD CARTS 十題的問法、檢查。開場、病史、系統回顧和身體評估直接用骨架。再寫三位病人：示範、變體（不同的真身）、遷移（沒看過的說法）。

如果新的主訴需要骨架裡沒有的題目或評估（例如神經學檢查），加在主訴模組自己的清單裡，不要改骨架：骨架一改，每個主訴的每個病例都要補回答。

## 一定要有的

- 每個病例都要寫 `review`。還沒經過臨床老師看過的，寫「未審查」，畫面上會顯示。
- 每一條教學重點都要對到一篇文獻，文獻要有 DOI，而且要查過是真的。
- 病例是虛構的。不要用真實病人的資料，也不要沿用教案裡的人物和原文。
