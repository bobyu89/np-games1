# 怎麼寫一個新病例

內容分兩層：

- **主訴模組**（例如 `chest-pain.ts`）：症影、四個真身、問題庫、評估項目、檢查項目。一個主訴寫一次。
- **病例**（例如 `c01a.ts`、`c01b.ts`）：只寫這位病人的部分。

同一個主訴的每個病例，畫面上的選項一模一樣，玩家沒辦法從「有哪些題目」猜出答案。

## 加一位病人（主訴已經有了）

1. 複製同一個主訴裡最像的病例檔，改檔名和 `id`。
2. 改這幾塊：

| 欄位 | 寫什麼 |
|---|---|
| `patient`、`reading` | 病人是誰、閱題卡上的三行字 |
| `vitals` | 生命徵象。會變差的病人另外寫 `worse` |
| `answers` | 主訴模組的每一題，這位病人怎麼回答。**每一題都要寫**，少一題會直接報錯 |
| `findings` | 每一項評估看到、聽到、摸到什麼 |
| `results` | 每一項檢查的結果；這一關等不到的寫 `pending` |
| `answer` | `truth` 是真身；`exclude` 是還要排除的真身和分數 |
| `summaries`、`sbar`、`explain` | 問題摘要、回報、說明的選項 |
| `timeline`、`safety` | 劇本的時間點、這一關的安全行動 |
| `lines` | 岑禾、沈渡和病人在固定時刻說的話 |
| `debrief` | 其他也可以的做法、重點、文獻 |

3. 在 `index.ts` 的 `CASES` 加一行；在 `src/ui/progress.ts` 的 `QUESTS` 加一行（`needs` 寫要先完成哪一張）。
4. 跑檢查：

```bash
npm run cases
```

## 線索

回答、評估結果、檢查結果後面都可以掛一條線索：

```ts
'q-tear': { say: '沒有，背不痛。', clue: {
  text: '沒有撕裂感，沒有痛到背',     // 顯示在畫面上的短句
  kind: 'neg',                        // pos 有的、neg 沒有的、info 背景
  tell: { form: 'dissection', dir: -1 }, // 讓「主動脈剝離」比較不像（1 是更像）
  why: '突然、像撕裂、痛到背，是主動脈剝離的典型說法。沒有，就比較不像。',
} },
```

- 有寫 `tell` 的線索，玩家拿到之後要自己選它指向哪一個真身。`why` 是岑禾的回應，答對答錯都會說。
- 一條線索如果有兩種合理的解讀，把另一種寫在 `alsoOk`。
- 一個病例大約放 8 到 10 條要解讀的線索。太多會拖慢節奏。
- 線索的代號不用自己取：問題 `q-tear` 的線索就是 `c-tear`。

## 安全行動

每個病例自己宣告哪些事一定要做到。分數加起來要是 9 分。

| 類型 | 意思 | 例子 |
|---|---|---|
| `call` | 病況變差之前通報 | 林秋 |
| `order` | 幾秒之內提出某項檢查 | 10 分鐘內提出心電圖 |
| `exclude` | 每個危險的真身，都要有一條讓它比較不像的線索 | 簡晴 |
| `explain` | 說明裡一定要有的那一句 | 交代什麼情況要馬上回來 |
| `calm` | 病人穩定，不需要敲值班鐘 | 簡晴 |

## 檢查器會擋什麼

- 少寫一題的回答、指到不存在的線索或真身、線索沒有任何行動拿得到。
- 要玩家解讀的線索沒有寫 `why`。
- 真身不是四個、沒有任何線索支持真身、要解讀的線索不夠拿滿分。
- 要求排除某個真身，卻沒有任何線索能讓它比較不像。
- 安全行動的分數不是 9 分、指到不存在的檢查。
- 教學重點指到不存在的文獻、DOI 格式不對。
- **照理想的打法玩不到安全達成和九十分**：表示病例裡有玩家做不到的要求。

## 加一隻症影（新的主訴）

寫一個主訴模組，照 `chest-pain.ts` 的樣子：四個真身（至少一個不危險的）、問題庫（分成開場、主訴、病史、系統回顧）、評估、檢查。再寫三位病人：示範、變體（不同的真身）、遷移（沒看過的說法）。

## 一定要有的

- 每個病例都要寫 `review`。還沒經過臨床老師看過的，寫「未審查」，畫面上會顯示。
- 每一條教學重點都要對到一篇文獻，文獻要有 DOI，而且要查過是真的。
- 病例是虛構的。不要用真實病人的資料。
