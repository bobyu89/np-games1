# 階段 1：設計目標（定稿 v1.1）

> 2026-11-11 定稿。之後要改目標，先改這一頁，再回頭檢查架構和內容。
>
> v1.1：加入 G10（病人血量）和 G11（檢查檢驗），過關條件改成「病人康復」。

## 1. 一句話

> 一款給 NP 學員的像素風回合制遊戲：每一關是一個 OSCE 主訴。病人會一直掉血，玩家要問對問題、做對評估讓他撐住，找出診斷、開對檢查檢驗，病人才會康復。

## 2. 已經確定的目標

| # | 目標 |
|---|---|
| G1 | 對象是 NP 學員 |
| G2 | 主題是 NP OSCE：從一個主訴出發，拆解到診斷 |
| G3 | 玩法是**回合制** |
| G4 | 美術是**像素風** |
| G5 | 步驟、用詞和分類對應 CDSS 臨床推理訓練系統：系統選擇 → 問診 → 身體評估 → 鑑別診斷 → 回饋 |
| G6 | **問診要全面**：現在病史（LQQOPERA 八項）、過去病史、系統回顧（ROS）三區都要問到 |
| G7 | 內容分科：內科、外科 |
| G8 | 病例**全部重新設計**，不使用 CDSS 的案例 |
| G9 | 這是一款**獨立的遊戲**，不屬於 CDSS 研究，也不連到 CDSS |
| G10 | **病人會一直掉血，問對問題才回血** |
| G11 | 找到診斷之後還要做**檢查檢驗**，之後病人才康復 |

## 3. 我先用的預設（你沒有反對，隨時可以改）

| # | 預設 |
|---|---|
| D1 | 診斷由玩家自己提出，遊戲不替玩家下結論 |
| D2 | 有練習和 OSCE 兩種模式：練習有提示和即時回饋；OSCE 計時，結束才看結果 |
| D3 | 用瀏覽器就能玩，手機優先 |
| D4 | 不用 AI，規則固定，同樣的操作一定得到同樣的結果 |
| D5 | 一個病例是一份資料檔，加新病例不用改程式 |
| D6 | 幾分鐘玩完一關 |
| D9 | 13 個問診面向第一次問都算「問對」，問得全面不會吃虧 |
| D10 | 血量歸零的說法是「病況惡化，這一關失敗」，不寫病人死亡 |
| D7 | 要不要做成研究，之後再決定。架構先把操作紀錄留好，到時候不用重做 |
| D8 | 人力是你加上我；不花錢買素材或服務 |

## 4. 設計原則

之後每個決定都拿這幾條來檢查。

1. **玩法就是教材**：要過關就得照臨床推理的方式做。
2. **問診要完整**：遊戲獎勵問得全面的人，不讓跳過變成捷徑。
3. **玩家自己下診斷**：遊戲揭開線索，不替玩家做結論。
4. **和 CDSS 說同一種語言**：步驟、用詞、分類一致。
5. **臨床正確不打折**：每條線索和每個診斷都有出處，簡化的地方要明講。

## 5. 第一版不做

AI 對話、帳號系統、玩家對戰、多國語言、治療和處置、需要實際操作技術的考站。

## 6. 怎樣算成功（數字之後再定）

| 面向 | 指標 |
|---|---|
| 學得到 | 玩過之後，問診和身體評估的完整度、鑑別診斷的正確率比之前好 |
| 想玩 | 沒人要求的情況下，多數學員會主動再挑戰一關 |
| 會玩 | 不用人教，學員能自己完成第一關 |
| 可信 | 每一關的內容通過臨床專家審查 |

## 7. 還沒回答、但不擋進度的問題

目標衝突時誰優先（教得對、好玩、好看、時程）；有沒有期限；有沒有其他人一起做。
