## 1. 一句話

> 你是霧脈公會的見習專科護理師。每位求診的人身旁都跟著一隻主訴化成的劫影。你要在時限內做焦點式的問診和身體評估，把霧照散，向考官說明你的判斷，再向病人說明下一步。

世界是奇幻的，**臨床是真的**：要做的事和真的專科護理師一模一樣。

## 2. 不知道考題，怎麼設計

你不會提前知道題目，也不需要知道。**這個遊戲不猜題，練的是「拿到任何主訴都會做」的方法。**

### 2.1 官方公開的三樣東西

| 公開資料 | 寫了什麼 | 我們怎麼用 |
|---|---|---|
| [口試流程及評分方式](https://www.mohw.gov.tw/dl-102764-a11e5aa6-8a16-40b9-9bae-869a76ea7e5c.html) | 考什麼能力、時間、配分（見第 3 節） | 試煉的規則和評分照它做 |
| [筆試範圍](https://www.mohw.gov.tw/dl-101170-3557121c-a298-4241-87cc-dc68c39f9cad.html) | 內科、外科各涵蓋哪些系統 | 題庫要涵蓋這些系統 |
| 同一份文件的參考書目 | 指定的健康評估和內科教科書 | 病例內容的出處 |

筆試範圍列的系統：

- **內科**：心血管、胸腔與呼吸、肝膽腸胃、神經、內分泌、腎臟泌尿、肌肉骨骼、血液、免疫過敏與感染、腫瘤急症、生命末期照護；另有急重症和中毒。
- **外科**：術前評估與手術合併症、消化、內分泌、神經、泌尿、骨科、整形外科、五官外科；另有外科重症和創傷。
- **各科共同**：營養、體液電解質與酸鹼、發燒、感染。

### 2.2 題庫的做法

1. **用主訴當單位，照系統鋪開。** 每個主訴都牽涉好幾個系統，例如胸痛會碰到心血管、胸腔、腸胃、肌肉骨骼。選一批常見的主訴，讓上面的系統都被碰到。
2. **每個主訴至少三個病例**：示範案、同主訴但病因不同的變體、沒看過的遷移案。其中一定要有一個危險的、一個常見而不危險的。
3. **試煉用抽的，而且會抽到故事裡沒練過的主訴。** 真的考試就是進場前兩分鐘才知道主訴，試煉要還原這種不確定。
4. **每年的考試規則做成設定。** 時間、配分、提醒的時間點都不寫死，明年公告後改設定就好。
5. **不用考古題，不承諾命中考題。** 內容只用公開的規定和教科書。

### 2.4 任何主訴都適用的骨架

遊戲反覆練的就是這一套，提示一章一章拿掉。步驟取自官方的口試流程；先教察覺、再教解讀和回應、最後反思的順序，參考 Tanner（2006）的臨床判斷模式。

| 步驟 | 做什麼 |
|---|---|
| 閱題 | 讀病人資料和主訴。先想：最危險的可能是什麼、最常見的是什麼、我要問什麼 |
| 開場 | 自我介紹、確認病人、關心他現在的不舒服、說明接下來要做什麼 |
| 焦點病史 | 主訴的特徵 → 危險訊號 → 相關的過去病史、用藥與過敏、家族史、社會史 → 相關的系統回顧 |
| 焦點身體評估 | 先看生命徵象，再評估相關系統。每一項先向病人說明目的、項目和部位 |
| 向考官報告 | 最可能的健康問題和理由；還要排除什麼 |
| 向病人說明 | 評估的結果、下一步的計畫、要注意的事 |

## 3. 對齊甄審（115 年度的規定，已核對原文）

- 進考場前 2 分鐘，在門口讀病人基本資料和主訴。
- 站內 15 分鐘是一整段，結束前 3 分鐘廣播提醒，自己掌握時間。
- 進場後依主訴做**焦點式**病史訪談、焦點式健康評估、臨床推理與決策。
- 向口試委員解釋病人可能的健康問題和理由。
- 對病人解釋評估結果與下一步計畫或注意事項。
- 做身體評估時，同時向病人說明檢查目的、項目和部位。
- 配分：病史詢問與身體診察 50% 至 60%，鑑別診斷與臨床推理決策 40% 至 50%。
- 兩位口試委員評分，60 分及格。
- 簡章另外寫到：考場裡不能用自己帶的聽診器和筆燈；有發紀錄用紙，離場要繳回。

這是今年的規定。第一批玩家考的是明年，公告後要再核對一次。

## 4. 世界觀

### 4.1 一條規則

**地點、組織、角色的外觀可以奇幻；臨床的東西一律照真的。** 症狀、病史、身體評估的手法、診斷和檢查的名稱、生命徵象的數值和單位，一個字都不改。

### 4.2 霧港和劫影

霧港依山傍海，有騎樓、雨棚、潮聲和公會的值班鐘。幾十年前，港城出現一種會凝結成形的霧。人在疼痛、喘不過氣、說不清自己怎麼了的時候，身旁有時會出現**劫影**。霧脈公會把每一次照護的觀察記進圖鑑，幫下一位值班的人找到問對問題的起點。

- **劫影跟著主訴，不跟著診斷。** 同一隻胸痛的劫影會出現在不同的病例。牠長什麼樣子不會洩漏答案，病名由這個病例的證據決定。
- **霧代表「你還不知道的」。** 你拿到的資料越多，劫影的輪廓越清楚。
- **病人的狀況不看劫影**，看生命徵象、病人的反應和臨床資料。
- 病人有名字、有生活、有自己擔心的事。

## 5. 主線

| 章 | 發生什麼 | 玩家要學會的 |
|---|---|---|
| 序章　遺失的一頁 | 檔案室淹水，圖鑑只剩劫影的外形。孟拓讓你接第一張委託 | 問、查、記錄；分清楚病人說的和量得到的 |
| 第一章　鐘聲之前 | 林秋想撐到交班，胸痛讓他停下來。街上另一個人也出現同一種劫影 | 同樣的外形，比較病程和危險程度；早一點通報 |
| 第二章　同一張面孔 | 不同街區的人，把同一種劫影叫成不同的名字 | 病人講法不同，也要問到同一個關鍵資訊 |
| 第三章　被蓋掉的紀錄 | 你找到公會舊的「一症一解」索引，重新追查被歸錯的委託 | 主動找反證，保留合理的不確定 |
| 終章　大霧值班夜 | 燈塔的燈熄了。門口同時有兩三位；之後上燈塔，看一位說「還撐得住」的人（第 23 節，已做） | 排優先順序、交班、回頭重評；不照病人自己給的答案看 |
| 尾聲　新索引 | 圖鑑改寫成症狀、危險訊號、證據的索引 | 用一個沒看過的病例證明學會了 |

主線本身就在講「不要一個症狀只想到一個答案」。太早認定答案是診斷錯誤的常見來源（Croskerry, 2003）。

## 6. 一關怎麼玩

### 6.1 六種行動

| 行動 | 內容 |
|---|---|
| 問診 | 問一個焦點問題，病人照病例的劇本回答 |
| 評估 | 觀察、生命徵象、焦點身體評估。先向病人說明再做 |
| 檢查與資料 | 看已經有的資料，或提出要做的檢查 |
| 推理 | 寫一句問題摘要，排鑑別診斷，把線索標成支持、反對或待查 |
| 通報 | 呼叫支援、向值班醫師回報、重新評估 |
| 說明與結案 | 向病人說明，向考官或團隊提交摘要 |

- **急的事隨時可以做。** 第一步就可以呼叫支援，不用等問完。例如疑似急性冠心症要在 10 分鐘內取得並判讀心電圖（Rao et al., 2025），胸痛那一關不能等問診全部做完才做。
- **每個行動花掉一段模擬的時間**，例如問一題 30 秒。時間到了劇本上的點，病人的狀況會變，例如血壓掉下來。延遲了還有補救的機會。
- 重複問同一題拿到同樣的線索，分數只算一次。

### 6.2 兩種模式

| | 委託 | 試弓 |
|---|---|---|
| 樣子 | 有劫影、有故事、有演出 | 中性的考場樣式，收起劇情和收藏 |
| 時間 | 模擬的時鐘，看字和操作選單不扣時間 | 閱題 2 分鐘，站內 15 分鐘的真實倒數，第 12 分鐘提醒 |
| 主訴 | 自己從委託板選 | 用抽的，可能沒練過 |
| 提示 | 孟拓會提示，圖鑑可以查 | 沒有 |
| 鑑別診斷 | 從清單選 | 第一版也從清單選，之後再加自己寫 |
| 回顧 | 每個階段都有 | 交卷後才有 |

之後再加第三種：刻意練習，只挑一種能力反覆練。

### 6.3 推理板

- 先寫一句問題摘要，例如「急性持續壓迫性胸痛合併冒冷汗」。
- 排出最可能的、最危險的、還要排除的。
- 每條線索可以連到好幾個假設，標成支持、反對或待查。
- 沒問到的、病人否認的、還不知道的，分開顯示。

### 6.4 關後回顧

1. **蒐集**：選一個影響判斷的時間點，看那一刻你知道什麼。
2. **分析**：比較你的做法、其他可以接受的做法、可能漏掉的關鍵。
3. **摘要**：寫下一個下次要做到的行動，帶進下一關。

回顧是模擬教學裡學習發生的地方（Fanning & Gaba, 2007）。

## 7. 評分

照官方的配分。試作的量尺共 100 分：

| 軌道 | 內容 |
|---|---|
| 資料收集與診察 55 | 焦點病史 25；生命徵象與焦點身體評估 20；取得同意與說明檢查 10 |
| 推理與決策 45 | 問題摘要和優先的鑑別 15；支持和反對的證據 10；照護、回報和重評 15；對病人說明 5 |

- 分數旁邊另外標**安全狀態**：達成、延遲補救、需要複核。
- 每一項量尺寫清楚看哪個行動、給幾分、有哪些可以接受的替代做法。同樣的操作一定得到同樣的分數。
- 遊戲的分數是訓練用的，不代表正式甄審的成績。

## 10. 美術和技術

- **畫風：手繪繪本風（2026-11-12 定案）。** 平塗、鉛筆描邊、紙的顆粒、低彩度的綠和土黃。網頁介面負責文字、表單和推理板，做成紙片的樣子；上面一塊手繪風的平面場景負責病人、劫影和演出。
  - 經過：先做了 3D 像素的定稿，你看過之後給了一組手繪繪本風的參考圖，同一個場景又做了一張繪本版來對照，你選了繪本版。兩張都留在 `prototypes/`。
  - 參考圖只當方向，沒有收進專案；角色、房間和構圖都是重新設計的。正式上線如果想要某位插畫家本人的味道，要找對方合作或授權。
  - 病人畫成人，不畫成動物：身體評估要看膚色、頸靜脈、水腫。可愛的部分放在劫影和道具上。
- **技術**：前端 React 加 TypeScript。規則核心是純 TypeScript，不碰畫面，之後可以原封不動搬到伺服器。後端用什麼語言還沒定，見 [`04-system-design.md`](04-system-design.md) 最上面的說明。
- **和 CDSS 的關係**：照你之前定的，獨立，不連。

## 13. 之後補上的（2026-11-12）

試玩互動原型之後，你覺得要更有深度，並且確認了三件事。細節在 [`06-progression.md`](06-progression.md)。

| 項目 | 做法 |
|---|---|

## 19. 名字出現在它該出現的地方（2026-11-12）

你試玩之後說：診斷的時候不要有世界觀的名字，該是什麼就說什麼。判讀的時候跳出那些詞，注意力會被拉開；名字可以有，但出現在它該出現的地方就好。

定下來的規則：**進了病室到看完回顧，畫面上的字只用臨床本來的說法。**

| 哪裡 | 用什麼話 | 例子 |
|---|---|---|

| 接委託之前的說明 | 在門口對一次：畫面上的四盞燈，就是這個主訴四個可能的診斷 | |

| 回顧 | 臨床的話 | 「每一個不能漏掉的診斷，都找到了讓它比較不像的線索。」 |
| 結案時孟拓的那一句 | 世界觀回來 | 「霧散了。……寫進圖鑑吧。」畫面右下角這時候才出現劫影的名字 |

| 主訴 | 用抽的。四十八位病人都可能出，沒遇過的比較容易抽到；不會連續兩次同一位；抽了不能重抽 | 一樣 |
| 閱題 | 抽完先看病人資料和「進門之前先想三件事」。不計時，按了「進場」才開始倒數 | 原本寫閱題 2 分鐘也要倒數。先不做：手機上被打斷的機會太多 |
| 時間 | 站內 15 分鐘，照真的時間倒數，看字和想事情也算；剩 3 分鐘提醒一次；時間到，手上有什麼就交什麼 | 一樣（第 3 節：站內 15 分鐘，結束前 3 分鐘提醒） |
| 提示 | 沒有。不能問孟拓；線索判讀對不對當下不說；劫影、霧和四盞燈都收起來；孟拓的位置換成「口試委員」 | 一樣 |
| 回顧 | 交卷之後才有。多一行：幾分、有沒有到 60 分的及格線、用了多久或是時間到 | 一樣 |
| 留下什麼 | 只留成績（最多 30 筆）。不寫圖鑑、不算完成委託 | 一樣（「收起劇情和收藏」） |
| 中途離開 | 回來可以接著考，倒數從離開的時候接下去 | 新的 |

及格線 60 分照第 3 節（115 年度的規定）。畫面上寫清楚：遊戲的分數是訓練用的，不代表正式甄審的成績。

要知道的事：

- 規則核心沒有改。試煉用的是「值班」那一層的規則（線索的方向自己選），再由畫面把提示和回饋收起來。
- 會抽到還沒送到的委託。之後在委託板遇到同一位病人會覺得眼熟；這是刻意的取捨，因為每個診斷現在只有一位病人。病例多了之後，可以留一批只給試煉用。
- 鑑別診斷還是從清單選，不是自己寫。

### 22.2 回報問題

回顧頁、設定頁、首頁的「關於」都有「回報問題」。選一種（內容有錯、操作卡住、建議、其他），寫一段話，匿名送出。除了他寫的字，只會帶：哪一種、在哪個畫面、哪一張委託（從回顧頁回報的時候）、哪一版、手機還是電腦。作者在管理頁（網址後面加 `#stats`）看得到。

這是內容品質的一條線：病例還沒有經過臨床老師審查，玩的人發現哪一句不對，要有地方說。

### 22.3 隱私說明

網址後面加 `#privacy`。照系統實際做的事寫：不登入的時候、登入的時候、匿名統計、回報問題、cookie、資料放在哪裡、保存多久。設定頁、首頁的「關於」、登入的那一頁都有連結。改了系統收什麼、存什麼，這一頁要跟著改（`app/src/ui/privacy.ts`）。

| 項目 | 做法 |
|---|---|
| 換畫面 | 淡進來、往上浮一點。首頁的標題和選單一個一個出現 |
| 故事的演出 | 公會大廳的故事演到某幾句，場景會跟著動：孟拓走到窗邊；馬凱走進大廳；講以前的事的時候整個大廳暗下來；「那天晚上，燈塔沒有亮」的時候窗外的燈熄掉；那一頁勘誤浮出來，講到第十二行的時候那一行亮起來 |

## 23. 霧港的五個診間，和終章（2026-11-13）

試玩之後的回饋：五章都在同一間病室裡，走到後面像在同一個地方打轉；故事停在第五章，沒有結尾。這一版做了兩件事。**四十八位病人的內容一個字都沒有改。**

### 23.1 一章換一個地方

公會在霧港有五個診間。每一章的委託在其中一間看；出診的委託照舊到碼頭的貨棧。

| 章 | 地方 | 為什麼去那裡（孟拓或費民在那一章開場說的） | 畫面上認得出來的東西 |
|---|---|---|---|
| 第一章 | 公會的病室 | 報到的地方 | 綠色的壁紙、窗外的樹、掛著的草藥 |
| 第二章 | 魚市口的診間 | 魚市口的人天沒亮就上工，喘了、痛了也不肯爬坡上來 | 白灰牆、畫了魚的磁磚牆腳、石板地；窗外是魚市的棚子和攤子；繩子上曬著魚乾和蒜頭 |
| 第三章 | 檔案室旁的舊病室 | 舊索引要一張一張對，離不開檔案室 | 牆上淹水留下的水痕；繩子上晾著一張一張舊索引；拱窗外是後院的銀杏 |
| 第四章 | 船塢的工寮 | 船塢在趕一艘船，沒有人肯放下手上的活走過來 | 直的木板牆、刷了瀝青的牆腳、沙土和刨花；門外的船台上有一艘造到一半的船；牆上掛著鋸子和木槌 |
| 第五章 | 坡上的靜室 | 這一章的話，在人來人往的地方問不出來 | 淺色的牆、草蓆、一面屏風；圓窗看下去是整個霧港，遠遠的是燈塔 |
| 終章 | 燈塔的值夜房 | 見 23.3 | 夜裡。圓的石牆、很深的拱窗、架上十五本值夜日誌、鐵爐 |

幾個決定：

- **病例上寫的是「來公會」，所以新的地方都是公會的診間**，不是別的機構。病人的話一句都不用改。
- **床、桌子、吊燈、值班鐘，和每個人站的位置，每個地方都一樣。**換地方只換看到的東西，不換操作。學員不用重新找按鈕。
- **下雨天是每個地方都有的變化**，不另外算一個地方。原本十二位「下雨天的病室」的病人，現在是各自那一章的地方、下雨天。
- 地方寫在主訴模組（`place`），不寫在每一個病例裡：一個主訴的委託都在同一間看。病例只在出診或下雨天的時候寫 `scene`。
- 委託板的標題帶地點（「第二章・魚市口的診間　風袋蛙｜喘」）；閱題那一頁第一行是地點；第一次踏進去有一句旁白。圖鑑的「場景」從五格變成八格，一章開一格。

### 23.2 終章前半：值班夜（三輪分流）

第五章走完，燈塔的燈熄了：出海的船看不到礁石，人一批一批送進公會。這一段不是病例，是三輪題目：**門口同時有兩三位，你只看得到站在門口十秒鐘看得到的東西。**每一輪兩個決定。

| 輪 | 門口的人 | 第一個決定：先看誰 | 第二個決定：一句話 |
|---|---|---|---|
| 一　大聲的和安靜的 | 抱著腳踝大喊十分痛的年輕人；說「我沒事，先看他」、一句話要換兩次氣的老太太 | 安靜的那一位 | 另一位交給孟拓：現在的狀況、請她先做什麼、什麼變化要叫你、你什麼時候回來 |
| 二　流血的和怪怪的 | 額頭流血、自己壓著走進來的人；今天下午才開始嗜睡、答非所問的老先生；腰痠三天來拿藥的人 | 意識改變的那一位 | 對馬凱回報三個人：先講最急的是誰、為什麼、要他做什麼 |
| 三　回頭 | 半個鐘頭前你說「等一下回來看你」的腹痛病人，現在安靜下來了；剛進門、手指劃傷的人 | 回去看等著的那一位 | 回到床邊先做什麼：叫他、重量、再摸一次肚子，跟半個鐘頭前比 |

- 沒有分數，不寫圖鑑。每個決定當下就有回饋（選錯也會說為什麼、該看誰），走完有一頁整理，附文獻。
- 這三件事（排優先順序、交班、回頭重新評估）是考站不考、值班第一天就會用到的。內容只到原則的層級，沒有寫檢傷的級數。
- 走完記一筆（和看過的故事記在同一個地方，所以會跟著存檔、匯出、同步）。可以重走。

### 23.3 終章後半：還撐得住

後半夜，送燈油的人從塔上帶下來一句話：歐律克勒亞說「胃不太舒服，還撐得住。塔上不用上來人。」十五年前，埃爾佩諾說的也是這一句；那一次孟拓看了索引，寫了一行字，讓他回去。這一次她不寫：**她讓玩家去看，自己跟在旁邊，只寫她的三行。**

- 這是第四十九位病人（C01E）：71 歲女性，胸痛模組，診斷是心因性。她不說「痛」，說悶、脹、像吃太飽；她自己先給了答案（胃）；心電圖沒有 ST 段上升。出力就悶、休息會好，到今天休息也不退，加上冒冷汗、噁心、下巴和背後發緊。
- 規則和其他委託完全一樣（值班階級的提示）。不一樣的只有她這個人：她是寫那本「一隻劫影一行字」的人，而舊索引上獨眼蛾那一行寫的就是「心」。**答案和索引一樣，可是玩家是一題一題問出來的。**結尾孟拓說的就是這件事：那一行字從來沒有寫錯，錯的是看到它就不再問了。
- 馬凱這一次爬完了那一百多階；他說的是「看完，我才簽」。孟拓超過五分鐘沒有人通報時接手敲鐘，說的是「這一次，我不等她說可以」。
- 結尾：燈是孟拓點回來的。歐律克勒亞留了三行字給玩家。勘誤的第十二行還是空的。
- 她不在委託板的章節裡、不會被試弓抽到、沒遇到之前不占圖鑑的分母；結案之後，她在圖鑑裡是「公會的人」那一欄，不在病人那一欄。

### 23.4 還沒有的

- **新的內容都還沒有經過臨床老師審查**：歐律克勒亞這一位，和三輪分流的題目。審查清單裡各有一份（`docs/review/chest-pain.md` 的最後一位、`docs/review/night.md`）。
- 值班夜只有三輪，每一輪的題目是固定的，走第二次就背得起來。它是示範這三件事怎麼想，不是題庫。
- 五個新地方只在無頭瀏覽器裡看過，還沒有在真的手機上看過顏色和可讀性。
- 燈塔那一間是夜景；其他地方還沒有白天、晚上的變化。

## 24. 口試倒數（2026-11-13）

115 年度甄審的口試是 115 年 12 月 5 日。首頁的標題底下、委託板「驗收」那一欄（試弓的上面）會顯示「距離口試還有 N 天」。

- 照裝置的日期算，每天自己更新；口試當天顯示「口試就是今天」，過了就不再顯示。
- 日期只寫在一個地方（`app/src/ui/exam.ts`），換年度改一行。這個日期是使用者給的，沒有另外和主辦單位的公告核對。
- 可以關：設定裡有「口試倒數」。遊戲公開之後，玩的人不一定都要考這一場，也有人看了倒數會更緊張。開關存在裝置上，不跟著進度同步。
- 倒數只是提醒，不改任何規則：不會因為快考了就解鎖什麼、也不會扣什麼。

## 25. Threads 的每日一案（2026-11-13）

遊戲有一個 Threads 帳號，每天發一位病人的閱題卡（他是誰、發生什麼事、進門之前先想的三件事），圖是那位病人在他那一章的地方。做法和設定在 [`social/README.md`](../social/README.md)。

- 只放進門之前本來就看得到的內容，不公布診斷：保護試弓的題庫，也不把還沒審查的結論當教材發出去。
- 每張圖、每段文字都帶「還沒有經過臨床老師審查」。
- 可以手動發，也可以每天早上自己發（要帳號主人先授權一次；沒有授權之前什麼都不發）。自己發的那一次由 Cloudflare 的定時器負責（跟遊戲的後端是同一個 Worker），GitHub 的排程晚一點當後備：GitHub 的排程不保證準時，第一天（2026-11-14）就沒有跑。
- 發文用的圖放在網站的 `social/` 底下，不進遊戲的離線快取，也不算遊戲換版。

## 26. 進門之前不先給方向，和角色、用字（2026-11-21）

試玩的回饋有四點：用字可以再精準、前言裡角色的定位不夠明確、有些字讓人看不懂自己在做什麼、有時候像是故意把人引到設定好的答案。病例的內容和難度沒有動，改的是「進門之前」和「畫面怎麼說明」。

**進門之前不先給方向**

回頭看了四十九張委託，進門之前有三個地方會把方向先說出來：

| 哪裡 | 原本 | 現在 |
|---|---|---|
| 委託的標題 | 板子上直接寫標題。標題常常就是那位病人的關鍵線索（「躺不平的夜」「從肚臍開始的」「壓不掉的紅點」） | 結案之前，板子和委託單只寫病人的名字和主訴；結案之後才換成標題（`questName`） |
| 「進門之前，先想三件事」 | 有些題目直接點出要比的東西、預設了處置或答案（「這位病人需要氧氣。要給多少？」「這些點，壓了會不會褪色？」） | 第一題都是「最危險的可能是什麼？」；另外兩題只問閱題卡上看得到的事，不點名哪一個診斷、不指定檢查的手法、不預設結果 |
| 孟拓進門的話 | 常常把這一張最關鍵的動作先講了（「先拿一片玻璃，壓給她看」「肚子要摸」「請他閉上眼睛站一下」），或是先評了病人自己的說法 | 只交代來的人、地點、這是哪個主訴的第幾位；主訴第一次出現時，講這個主訴通用的做法（例如腫脹先分一邊還是兩邊） |

- 出診的時候孟拓會說「值班鐘我帶來了，用不用由你決定」，**每一張出診都說同一句**。原本只有緊急的那幾張會提值班鐘，提了就等於說這一張要敲。
- 問診和評估的選單本來就把每一題、每一項都列出來，所以拿掉這些話，找得到的東西沒有變少；原本那些話要教的，回顧裡都還在。
- 沒有動的：見習和巡診的階級，遊戲仍然會在重要的線索停下來、告訴你方向（第 7 節的提示階梯）；敲了鐘之後孟拓的回應、結案之後的回顧。那些是做了之後的回饋，不是做之前的引導。
- Threads 的每日一案用的是同一張閱題卡，題目跟著換了（`social/schedule.json` 和圖重新產生；已經發出去的不動）。

**角色**

- 序章把每個人的身分說出來：你是剛結束訓練的見習專科護理師；孟拓是資深專科護理師，帶你的人；馬凱是值班醫師，病人你先看、看完向他回報，檢查和用藥由他決定；費民管檔案室和圖鑑。也說了「委託」是什麼：一張委託就是一位病人。
- 委託單多一段「你的角色和任務」，像考站門口的指引：你是誰（照現在的階級寫）、旁邊有誰、這一張要完成哪五件事。試弓的閱題頁也有（那裡寫的是考生和口試委員）。

**用字**

- 委託單上「畫面怎麼操作」改寫：四盞燈是四個鑑別診斷、遊戲什麼時候會停下來問你、「穩定度」和「霧」各是什麼、時間什麼時候走、值班鐘和「問孟拓」各在什麼時候用。結過一張之後這一段收成一行，要看再點開。
- 第一張委託孟拓一步一步帶的那幾句，改成先說「現在要做哪幾件事」，再說按哪裡。
- 解讀線索的方向，按鈕從「排除它」改成「不支持它」：一條線索只是讓一個診斷比較不像，還不到排除。
- **按鈕寫的是功能，不是故事裡的名字。** 回饋的例子是「值班鐘」：按鈕上只有這三個字，不知道按了會怎樣。病室裡的三個地方照這個原則改：「值班鐘」→「緊急通報」（按了之後是「已通報」），確認的那一頁說明它就是敲值班鐘、什麼時候按、病人穩定的話改走「向醫師回報」；「問孟拓」→「要提示」；「霧 100%」→「未釐清 100%」。故事裡（序章、孟拓的話、圖鑑）還是叫值班鐘和霧。回顧裡的評語跟著改成「緊急通報」。

**同一天的第二輪：別的地方也會把答案演出來**

請別的 AI 讀了一遍 repo，它們指出的幾處，對照程式是對的，這一輪修掉：

| 哪裡 | 原本 | 現在 |
|---|---|---|
| 「要提示」（`hintFor`） | 下了診斷之後：只對要通報的病人問「該讓誰知道？」；直接點名該做的檢查（「有一項檢查要先做：心電圖」）；點名還沒談到的危險診斷 | 只看玩家做了什麼。每一位病人都問同一句「先判斷他等不等得了」；只說「還沒有提出任何檢查」，不說是哪一項；只提玩家自己寫在「要排除」裡的診斷 |
| 四盞燈 | 線索判斷錯了，設定好的那一盞照樣變亮或變暗 | 只有判斷對的線索會讓燈變；判斷錯，燈不動 |
| 大廳的故事 | 第四位病人之前先說「只剩『血管急症』那一盞還沒亮過」；「有兩位不太穩」 | 不說還剩哪一盞、哪幾位急 |
| 值班夜的一句話 | 三輪裡對的那一句都是最長的（63 字對 13、17 字） | 三個選項拉到差不多長；錯的選項一樣是完整的一段話，錯在內容 |

**還沒有修、要另外決定的**

- **病例裡的選項，最長的就是答案。** 量過：四十九張裡，「一句話摘要」滿分的那一句全部是最長的，平均是其他選項的 3.6 倍；回報醫師的判斷也是四十九張全部。向病人說明，對的平均 49 字、錯的 21 字。不用讀內容，挑最長的就會對。這要重寫大約四百個錯的選項（寫成一樣長、看起來合理、錯在臨床判斷上），是病例內容的改動，還沒有動。
- **一個主訴四個診斷、各一位病人**：做到同一個主訴的第四位，用刪去法就知道答案。故事不再提醒這件事，但是圖鑑上看得出來。試弓是抽題，不受影響。
- **考站的順序和真的急症不一樣**（要先下診斷才能提出檢查、才開始算惡化的時間）：原本就列在要請臨床老師回答的問題裡，沒有動。

測試：`progress.test.ts`（標題結案才出現；值班鐘那一句只在出診、而且每一張都一樣；提問都是三題、第一題一樣；值班夜的選項差不多長）、`engine.test.ts`（提示不點名檢查、不點名玩家沒寫上去的診斷、急和不急的病人聽到同一句；判斷錯的線索燈不動）。提問和進門的話有沒有帶方向，機器驗不出來，是一張一張讀過改的；之後新增病例照上面那張表寫。

## 27. 霧海群島：航海圖、五島長老會、常駐的人、歸鄉的消息、海神的風暴（2026-11-21）

研究主持人要的是「有深度的系統，不只是背景」，而且整個遊戲要像一張航海圖。兩條底線照守：**病室裡只用臨床的話，老醫生的提示要通過不洩題的測試；病例內容不動，新的東西都加在病例外面。**

**五座島（`data/islands.ts`）**：本島（公會大廳、第一章的病室、燈塔）、斯克里亞（第二章，魚市口）、法羅斯（第三章，檔案室和舊病室）、拉莫斯（第四章，船塢的工寮）、歐吉吉亞（第五章，坡上的靜室）。一章一座島，章節和病例都沒有重排，所以病例裡寫的「第三章的委託」「這一章的人」都還對。每座島都有碼頭的貨棧，出診算在那一章的島。

**航海圖（`ui/SeaChart.tsx`）**：大廳的委託板上面是一張航海圖：羅盤、方位線、水深數字、巡診船的航線、本島岬角的燈塔。去過的島寫上結了幾張；還沒去的蓋在霧裡。點一座島，底下只列那座島的委託；巡診船停在現在走到的那一章。

**五島長老會（老醫生）**：每座島一位，本島的是會首。
- 每一位有一種問法（專長），也有一種盲點：埃普只信摸得到的、諾可只看數字、聶思錨定在舊案例、狄墨太急、雅蕾順著病人的話走。
- **病室裡可以請教（第二章起，`core/elders.ts`）**：「要提示」會讓你選孟拓或去過的島上的老醫生。老醫生要打燈號請過來，花時間（10～60 秒）；值班之後跟孟拓共用一張委託三次的上限（故事裡叫燈油）。他們只看你這一場做了什麼、還沒做什麼（`gaps`），每一位照自己的順序提，**而且永遠不提某幾類**。
- **回顧**：最後一次請教如果他漏了東西，回顧多一題「那時候你還沒做、他也沒提的是哪一項？」另外兩個選項是那時候你已經做完的，選了一定不對。不計分。練的是看出別人的推理偏誤。
- **主線**：十五年前要不要把勘誤訂在第一頁，是長老會表決的，三比二不訂。一章到一座島，見到那一位，聽他當年怎麼投、為什麼；第五章走完，長老會重新表決，五票訂上去（`BEATS` 的 `council`，在終章之前）。
- 測試（`core/elders.test.ts`）：五位 × 四十九張 × 理想打法的每一步，提示都不出現任何檢查名、不出現玩家沒寫上去的診斷；同一個主訴的四位病人，同樣的行動聽到的是同一句（名字除外）；他不提的那幾類，就算還沒做也不會從他嘴裡出現。

**五位常駐的人**：每間診間一位（歐雅、娜希、朵蒂、門特、瑪拉）。進門那一句旁白會帶到他們；那間診間結過一張案之後，場景卡上出現他們和他們的習慣：照原話記、看不清的留白、交班時一樣一樣念、屏風拉不攏不能用。不進病室的對話、不給提示，不會洩題。

**六位主角的直覺與盲點**：選角的卡片上看得到。每一張委託的回顧多一題選讀的反思（照你選的那一位的盲點問），不用作答、不計分、不影響提示，所以選誰都一樣公平。

**歸鄉的消息**：四十八句後日談改成跟表現連動。診斷對、也回應了病人擔心的事，才會收到他的近況（回顧裡和圖鑑上）；沒做到的，寫「由公會的前輩接手安頓」，重接做到了才解鎖。每一張都有回應擔心的那一句，所以每一位都拿得到。

**海神的風暴（`data/tides.ts`）**：每一章走完，那座島的委託板上多一張選讀的推演：這一章看過的兩位同一刻到門口，先看誰、另一位怎麼交代。用的是終章值班夜的同一個畫面；只用他們進門那一刻看得到的樣子，不加病史。三個選項差不多長。

**故事的三個漏洞，這樣補**：
- 淹水不是巧合：檔案庫在地勢低的法羅斯，是十五年來第一次的大潮；四十天霧開始之前也是一場大潮。終章燈熄的那一晚，法羅斯又傳來大潮的燈號。
- 舊索引為什麼沒有糊掉：費民十五年前用油布包好、鎖在鉛盒裡，塞在最底下；圖鑑放在開架上，所以泡爛了。這也證明他「拆了，沒有燒」。
- 劫影和四盞燈的規則：港城的人都看得見劫影，所以才知道要來公會；劫影只描得出哪裡不舒服。四盞燈是公會做的「明眼燈」，只跟著你判斷對的線索亮或暗；試弓不掛燈，因為考的是你，不是燈。

還沒驗證：老醫生、海神的風暴和所有新的對白，跟其他內容一樣還沒經過臨床老師審查；海神的風暴的情境是推演。


## 28. 歸航記：用《奧德賽》串起整個故事（2026-11-21）

整體設計和取捨寫在 `docs/07-odyssey.md`；這裡記實際做了什麼。

- **改名**：地點、公會的人、長老、常駐的人、主角、十二劫影全部換成史詩風的名字（對照表在 07 那一份）。病人的名字不換。遊戲名是《霧脈公會：歸航記》，網址和 Threads 帳號不動；已經發出去的每日一案不動，之後的貼文本來就沒有用到改名的詞。症影改叫劫影，驗證器兩個詞都擋。
- **稱號**：人物的身分後面加史詩的固定稱號（明眼的孟拓、數潮的諾可、善記的伊安……），稱號就是那個人的性格，也是盲點。

- **十二斧之試**：試弓及格（60 分）一次，記一筆 `axe:<主訴>`。終章走完之後，大廳和試弓的說明頁多一排十二把斧頭；抽題時還沒亮的那幾種主訴，抽到的機會多四倍（終章之前不偏）。十二把都亮，播「終篇　英雄歸來」。
- **航海圖**：羅盤下寫「霧海」；終章走完，多一條從外海回伊塔洛斯的歸航線。
- 底線照舊：病室裡只用臨床的話；老醫生的提示照舊只看玩家做了什麼。劫的陷阱是依臨床推理常見的錯誤寫的，跟病例一樣，還沒有經過臨床老師審查。


## 29. 一劫一座島、前導片（2026-11-21）

- **十二座島**：研究主持人選「一劫一座島」。伊塔洛斯是家，第一章的獨眼巨人之劫也在這裡（第一天在本島報到的故事不動），另外十一座外島各一種劫影：埃俄利亞（喘）、斯克里亞（腹痛）、特里納基亞（發燒）、法羅斯（頭痛）、拉莫斯（背痛）、帕納索（腳痛）、卡律布狄斯（腫脹）、洛托法吉（排泄物）、埃埃亞（疹子）、歐吉吉亞（體重減輕）、辛梅里亞（感覺異常）。所以是十二座，不是原本說的十三座。
- 章不變。每一章最大的那座島（斯克里亞、法羅斯、拉莫斯、歐吉吉亞）照舊有長老、常駐的人和海神的風暴；同一章的小島從那座大島搭船過去。七座新島的診間先借同一章大島那一間的畫（`art/ward.js` 的 `ROOM_ART`），名字和進門的旁白是自己的。
- 篇章改成一座島一篇，加上歸航、十二斧，共十四篇。病例的內容不動，只換了主訴平常在哪一間（`place`）。
- **前導片**：`trailer/`，用 HyperFrames 做，52 秒，沒有聲音。畫面全部截自遊戲本身的程式美術。第一次打開、選主角之前播（可以跳過；手機直向播直式；不進離線快取，沒網路就跳過），圖鑑的「公會」頁可以重看。另外輸出一份直式 1080p 給 Threads。

- **下一步**（研究主持人回饋：一次太多東西、不知道在幹嘛）：大廳最上面固定一張卡，只說一件現在該做的事、為什麼，按一下直接帶過去（`progress.ts` 的 `nextStep`）。順序：沒結案的那一張 → 下一張委託（第一張時說明一張委託的流程；到一座新島時說明航海圖）→ 值班夜 → 燈塔 → 十二斧 → 寫滿圖鑑。卡片下面最多一句「選做」（`sideStep`：剛走完一章的海神的風暴，或第一次的試弓）。
- 還沒輪到的東西不先擺出來：上鎖的海神的風暴、終章和試弓的格子拿掉了，輪到的時候由「下一步」先介紹；一座島的篇章，在那座島結過一張委託之後才出現。

- **你在哪裡**（研究主持人回饋：從首頁看不出進度、到哪了、現在要幹嘛，進去之後更迷茫）：首頁「繼續遊戲」底下直接寫下一步，下面一條五章加終章的進度（`progress.ts` 的 `journey`、`ui/Journey.tsx`）；大廳的「下一步」卡最上面也是這一條。故事段落的按鈕寫「繼續（3／12）」，並說明看完會回到委託板。航海圖和整張委託板預設收起來，大廳平常只看到「下一步」那一張。

- **首頁一顆大按鈕、大廳先看地圖**（研究主持人：要有地圖；按鈕不能都一樣大；開始遊戲 → 看地圖進度 → 再選症狀）：首頁只剩「開始／繼續遊戲」一顆大按鈕和進度，底下一排小按鈕「設定、關於、聲音」；帳號與同步放進設定的最上面。大廳分兩頁：地圖頁（進度、下一步、航海圖，終章和試弓開了才出現）→ 點一座島 → 島嶼頁（這座島的劫影和症狀、委託、海神的風暴、篇章，最上面「回地圖」）。手機直向在地圖頁不畫大廳的插圖，故事段落才畫。

- **島名看不出要做什麼**（研究主持人回饋）：航海圖上每座島的名字底下寫症狀和進度（「胸痛 1/4」）；島嶼頁的標題先寫症狀，再一句白話說這裡的病人和一張委託要做什麼，接著是「提示・這個症狀最容易犯的錯」（劫的陷阱），神話島名放小字；「下一步」也帶上症狀。前導片在地圖頁和首頁的「關於・前導片」都看得到。

## 34. 練習的深度：先自己想、刻意練習、錯題隔幾天回來（2026-11-24）

用文獻佐證的路線定了之後，接著加深「練習」本身。三件事都不改計分、不改病例內容。

- **下診斷先自由作答**（`ui/freetext.ts`、`data/aliases.ts`）：第一次按「下診斷」，先不看四盞燈，自己寫想到的診斷（中英文都可以，最多 8 個），再按「對照四盞燈」看每一個對到哪個方向，以及「你沒想到的方向」；可以跳過。選四盞燈是辨認，先寫是回想，練的是腦子裡真的有沒有這幾個診斷（第 26 節「選單是辨認不是回憶」的限制，這裡補上一半）。
  - 比對只看字：每個方向底下列它涵蓋的病名、英文和縮寫（48 個方向、571 個寫法）。英文和縮寫整個字比（MI 不會對到 migraine），中文照包含；長的寫法蓋過包在裡面的短寫法（「過敏性紫斑」不算「過敏」）。不叫 AI、不判斷寫得好不好、**不計分**。
  - 寫的字只留在這一場（`Board.written`），回顧的「分析」會列出來，並說這一關的診斷方向你有沒有自己想到；不進存檔、不上傳、不進統計。
  - 測試擋：每個方向至少三個寫法、同一隻劫影裡一個寫法只對一個方向、每位病人的真正方向都對得到。
- **刻意練習**（`ui/drill.ts`、`ui/Drill.tsx`）：大廳「刻意練習」，一次只練一個環節，每題馬上有回饋，可以一直重來。
  - 線索解讀（6 題）：一條線索，選它讓哪個診斷更像或比較不像；判定和病室一樣（`tell` 或 `alsoOk`），回饋是孟拓的 `why`。你在病室裡還沒解讀對過的線索先出，同一位病人一輪最多兩題。
  - 問題摘要（4 題）、回報的評估（4 題）：給重點線索和生命徵象，從病例原本的選項挑最好的那一句，回饋是每個選項的 `note`。
  - 題目只從看過的病人出（結過案的委託、考過的試弓），不劇透。不計分、不寫圖鑑、**不算打卡**（打卡照第 31 節：結案一張委託或交一次試弓）。這一輪的結果不存。
- **錯題的間隔複習**（`ui/review.ts`）：一場的診斷沒對到、或掉進那個主訴的陷阱，大約 3 天後出現在大廳「錯題複習」；那一次做對了，再隔 7 天回來一次；再對就畢業，中途又錯從頭算。間隔還沒到就重做不算一次複習（間隔本身就是練習）。
  - 在哪裡錯就在哪裡重來：試弓錯的用試弓重考（直接閱題，不用抽），委託錯的重接那張委託。
  - 全部從存檔裡「最近幾場」（`plays`）算出來，沒有新的存檔欄位，所以登入同步、匯出匯入都跟著走，舊的備份格式不用升版。
  - 回顧最後一頁會提醒：這一位幾天後會回來。

## 35. 看練習有沒有在發揮作用：匿名統計多幾個「有沒有」（2026-11-26）

SWOT 裡最大的劣勢是沒有成效數據。不另建資料庫：後端本來就有匿名統計（Durable Object 裡的 SQLite），在同一張表加欄位。

- 結案和試弓多送三個 0／1：`tr` 有沒有掉進陷阱、`rv` 這一場是不是錯題複習（記之前的到期清單裡有這一位）、`w` 下診斷前自己寫的有沒有想到正確方向（沒寫就不送）。新的事件 `drill`：做完一輪刻意練習，送種類、對幾題、一共幾題，不記哪一位病人。
- **不送任何文字**：自由作答寫的病名、刻意練習選了哪一句都不送。規則照舊：選了「可以回傳」才送；隱私說明和詢問時的說明都補上了（隱私說明更新日 2026-11-26）。
- 舊的資料庫開起來自動補欄位（`worker/src/core.ts` 的 `migrate`）；舊版遊戲送來的事件，這幾欄是空的，也不算進新指標，所以比的都是同一版之後的資料。
- 管理頁（`#stats`）多「練習有沒有在發揮作用」：一般場次 vs 錯題複習的重考，各自的診斷正確和掉進陷阱比例；自己先寫想到正確方向的比例；每一種刻意練習的答對率。CSV 尾端多 `trapped, review, recall, drill, ok, total`。
- 這些是**內部指標**：只有同意回傳的人、沒有對照組、匿名端點擋不住灌水。用來看功能有沒有在用、方向對不對；要寫成研究或發表，要另外走 IRB（`worker/README.md` 同一段）。

## 36. 管理頁做成圖表面板（2026-11-26）

管理頁（`#stats`）從表格升級成 BI 面板，選 A：圖在遊戲自己的頁面畫，資料不經過第三方（不接 Looker Studio、Power BI）。圖表不用套件，SVG 自己畫（`app/src/ui/StatsCharts.tsx`）。

- **四張圖**：每天的裝置數、結案數、試弓數（折線）；沒結案的停在哪一段（橫條）；每一位病人的診斷正確率（12 個主訴 × 4 位病人的熱圖，不到 3 場的格子畫斜線、不給顏色）；練習指標每週的變化（四條比例線：一般和重考的診斷正確、先寫想到正確方向、刻意練習答對）。
- **畫法照 dataviz 的規則**：一張圖一個 y 軸、同一個單位；四個系列色用驗證腳本在 `#fffaf0` 底上檢查過（亮度、彩度、色盲分辨、對比都過），順序固定；熱圖只用一個色相淺到深；線尾直接寫名字，也有圖例；滑過去有十字線和數字；每張圖底下都可以攤開看表格。手機上圖在框裡左右滑，不縮到看不清楚。
- **後端多給兩樣**（`worker/src/core.ts`）：每天多試弓和刻意練習的次數；`weeks`：練習指標照週（星期一開頭）分開，最多 26 週。
