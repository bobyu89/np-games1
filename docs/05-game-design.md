# 遊戲企劃（草稿，等你確認）

> 2026-11-11｜這一頁定「這是一款什麼遊戲」：世界觀、角色、主線、一關怎麼玩、開場、動態、美術定調。
> 規則的細節在 [架構](02-architecture.md)，前後端在 [整體系統設計](04-system-design.md)。
> 這一頁確認之前，我不動程式。

## 1. 一句話

> 你是魔法專科護理師公會的見習專師。每一位來求診的人身後都躲著一隻看不清的霧獸。你要在時限內問對問題、做對評估，把霧照散，向主治醫師報告，通過年底的資格試煉。

世界是奇幻的，**臨床是真的**：要做的事和現在的專科護理師一模一樣。

## 3. 世界觀

### 3.1 一條規則

**地點、組織、角色、道具的外觀可以奇幻；臨床的東西一律照真的。**

照真的、一個字都不改的：
- 13 個問診面向和它們的名稱
- 身體評估的手法和順序
- 症狀、病史、危險因子
- 診斷的名稱、檢查檢驗的名稱和判讀
- 教學重點和出處

例子：心電圖在畫面上可以是一顆會發光的水晶，但名字還是「12 導程心電圖」，結果也是真的心電圖判讀。

### 3.2 對照表

名字都是我先取的，可以改。

| 現實 | 遊戲裡 |
|---|---|
| 醫院 | **提燈公會**，本部叫「燈塔」 |
| 專科護理師 | 專科護理師（公會的正式成員） |
| 專師訓練學員 | 見習專師，就是玩家 |
| 帶你的學姊 | 引路的資深專師 |
| 主治醫師 | 公會的主治醫師。你做完評估要向他報告 |
| 內科、外科 | 內科廳、外科廳 |
| 病人 | 來求診的人：村民、旅人、工匠。年齡、病史、症狀都照真的 |
| 一個主訴 | 委託板上的一張委託 |
| 還不知道的診斷 | **霧獸**：躲在霧後面，問對了霧才散，最後現出真面目 |
| 臨床推理 | **提燈的光**：你問得越對，燈越亮，霧越薄 |
| 練習 | 委託 |
| OSCE | 資格試煉。畫面上仍然寫 OSCE |
| 15 分鐘的考站 | 一只沙漏：12 分鐘蒐集線索，3 分鐘報告 |
| 疾病筆記 | 霧獸圖鑑 |

為什麼用「提燈」：提燈是護理的象徵，也剛好說明這個遊戲在做什麼。不是打病人，是把看不清的東西照清楚。

## 4. 角色

| 角色 | 作用 |
|---|---|
| 你 | 見習專師。可以取名、選外型 |
| 學姊 | 教你怎麼玩；委託裡給提示；每一關結束帶你回顧 |
| 主治醫師 | 你向他報告診斷和建議的檢查。專師是在醫師監督下工作的，所以用「報告」取代「自己下診斷」 |
| 來求診的人 | 每位有名字、年齡和一句個性 |
| 試煉官 | 資格試煉的考官，不給提示 |
| 霧獸 | 每個診斷一隻。過關後收進圖鑑 |

## 5. 主線

1. **序章：報到。** 學姊帶你接第一位求診的人，一邊做一邊教。
2. **委託。** 內科廳和外科廳各有一面委託板。每張委託是一個主訴。
3. **升階。** 見習專師 → 專師 → 資深專師。靠完成委託和圖鑑累積。
4. **資格試煉。** 故事的倒數是「距離試煉還有幾週」，和玩家真實的目標是同一個。試煉不分廳、主訴隨機、有沙漏、沒有提示。

## 6. 一關怎麼玩

流程不變：系統選擇 → 問診 → 身體評估 → 向主治醫師報告診斷 → 開檢查檢驗 → 康復 → 回顧。

| | 委託（練習） | 資格試煉（OSCE） |
|---|---|---|
| 時間 | 沒有沙漏。回合制，每回合病人掉血 | **15 分鐘的沙漏**：12 分鐘蒐集線索，3 分鐘報告 |
| 蒐集線索 | 問診和身體評估，可以來回 | 同左，沙漏的 12 分鐘走完就自動進報告 |
| 報告 | 向主治醫師報告，錯了可以再試 | 3 分鐘內說出主診斷、鑑別診斷，只有一次機會 |
| 提示 | 學姊會提醒、有燈號 | 沒有 |
| 病人掉血 | 每回合掉 | 每回合掉（等你確認，見第 11 節） |
| 回顧 | 每個階段都有 | 整關結束才有 |

試煉的沙漏是真的時間，不是回合數。它和考場一樣不能延長。

## 7. 序章：前五分鐘

目標：不用看說明，玩家就能自己打贏第一關。

| 段落 | 發生什麼 | 教什麼 |
|---|---|---|
| 開場，約 30 秒 | 黑畫面上三行字，交代霧和提燈。接著是燈塔的大廳 | 世界觀 |
| 報到 | 學姊把一盞燈交給你：「燈不會自己亮。你問對一個問題，它才亮一點。」 | 核心比喻 |
| 第一位求診的人 | 他按著胸口，身後一團霧。學姊：「先問他哪裡不舒服。」 | 問一題，燈亮、霧薄、病人回血 |
| 追問 | 學姊：「再問深一點。有些線索要追問才出得來。」 | 關鍵線索 |
| 霧獸反擊 | 霧獸撲過來，病人掉血。學姊：「拖越久，他越撐不住。」 | 時間壓力 |
| 身體評估 | 學姊：「聽聽他的心音。照順序來：視、觸、叩、聽。」 | 身體評估和順序 |
| 報告 | 你向主治醫師報告。霧散開，霧獸現形 | 提出診斷 |
| 檢查 | 開對檢查，病人康復 | 確認診斷 |
| 結尾 | 第一張圖鑑。學姊：「距離資格試煉還有十二週。」委託板打開 | 接下來要做什麼 |

- 序章不會失敗。
- 按鈕慢慢開放：序章先教現在病史，第二張委託加過去病史和系統回顧。之後 13 個面向都在。
- 對話都可以點一下跳過。

## 8. 動態清單

先把這些做到位，再加別的。

| 類別 | 動態 |
|---|---|
| 待機 | 求診的人在呼吸；霧在飄；燈火在晃 |
| 開戰 | 「委託：胸痛」的橫幅掃進來，霧獸從霧裡浮現 |
| 問對了 | 燈變亮一階；霧被光推開一層；霧獸往後縮 |
| 關鍵線索 | 燈光爆開，金色的火花，橫幅「關鍵線索！」 |
| 回血、掉血 | 數字從病人身上飄出來；血條慢慢長回去或縮短 |
| 霧獸反擊 | 霧獸往前撲，鏡頭晃一下，病人往後縮 |
| 白過一回合 | 燈閃一下又暗掉，霧獸冒出「…」 |
| 沙漏 | 沙子一直在流。剩一分鐘變紅、加快閃 |
| 報告 | 鏡頭轉向主治醫師，他點頭或皺眉 |
| 揭曉 | 光把霧整個吹散，霧獸現出真面目，名字的橫幅滑進來 |
| 康復 | 霧獸縮小、被收進圖鑑；病人站起來 |
| 升階、圖鑑 | 徽章蓋章；新的一頁翻開 |

聲音用程式合成，不需要音檔。

## 9. 遊戲和教育的橋

每一關結束由學姊帶回顧，並把遊戲裡的表現換算成 OSCE 評分表的樣子：「這如果是真的考站，你會在哪幾項拿到分數。」模擬教學裡，回顧是學習發生的地方（Fanning & Gaba, 2007）。

各廳的委託都混進「真面目和第一印象不一樣」的關卡。太早認定一個答案是診斷錯誤的常見來源（Croskerry, 2003），這種關卡就是在練這個。

## 10. 美術定調

### 10.1 找到的參考

| 作品 | 類型 | 值得借的 |
|---|---|---|
| [Echo Generation](https://store.steampowered.com/app/1072300/Echo_Generation_Midnight_Edition/) | 方塊（voxel）模型的回合制 RPG，官方自己叫「3D pixel look」 | 最接近我們要的：3D 像素加回合制。製作團隊說[動作用流暢的 3D 動畫，不一格一格畫；有機的怪物用乾淨的造型加像素貼圖](https://80.lv/articles/echo-generation-creating-a-turn-based-adventure-game/) |
| [The Touryst](https://store.steampowered.com/app/1796410/The_Touryst/) | 方塊世界的探索遊戲 | 方塊角色配乾淨的光影，不會像積木玩具 |
| [Octopath Traveler II](https://store.steampowered.com/app/1971650/OCTOPATH_TRAVELER_II/) | HD-2D：2D 像素角色放在 3D 場景 | 場景的景深、光線、粒子，讓像素畫面有空間感 |
| [three.js 的像素化範例](https://threejs.org/examples/webgl_postprocessing_pixel.html) | 技術示範 | 證明「把 3D 畫成低解析度像素、加一個像素寬的描邊」在瀏覽器裡跑得動 |
| [3D Pixel Art Rendering](https://davidholland.netlify.app/articles/3d-pixel-art-rendering) | 技術文章 | 做法：低解析度算圖、鏡頭對齊像素格、用深度和法線描邊、卡通式的平塗光影 |
| [Understaffed in the Underworld](https://enderesting.itch.io/understaffed) | 2D 像素，替怪物看病的診所 | 奇幻診所的氣氛：有限的配色、求診者一句話講主訴、畫面上的時鐘 |

另外找到一款同類產品：[The Ward](https://windowdoom.itch.io/the-ward)，瀏覽器上的臨床模擬 RPG，玩家是醫師，英文。它偏文字和數值，不是美術的參考。

要老實說的：
- **醫療題材的 3D 像素作品，做得好的我沒有找到。** 找到的多半是單賣的素材，例如[付費的方塊醫師模型](https://mrmgames.itch.io/voxel-doctor-character-3d-low-poly-model)和[低面數的醫院素材包](https://atomicrealm.itch.io/hospital-assets)。這表示沒有現成的樣子可以照著做，也表示做出來會有辨識度。
- Echo Generation、The Touryst、Octopath Traveler II 我只看了官方介紹和報導，沒有看到遊戲內的截圖。請你點進去看畫面，告訴我哪一個最接近你想的。

### 10.2 我建議的方向

**用方塊風的 3D 模型，畫成低解析度的像素。** 角色、霧獸、場景都是 3D 的，算圖時降到低解析度、加一個像素寬的描邊、用平塗的光影，再整數倍放大。文字和按鈕維持像素字體。

| 理由 | 說明 |
|---|---|
| 動態幾乎是送的 | 呼吸、撲過來、晃動、鏡頭推近，都是移動和旋轉 3D 物件。2D 像素要一格一格重畫 |
| 風格一致 | 所有東西用同一套光影算出來，不會有的精緻、有的粗糙 |
| 我做得出來 | 方塊模型可以用程式一格一格堆。手繪 2D 像素是我最弱的一環，之前的佔位圖你也覺得不夠 |
| 配合世界觀 | 提燈的光、霧的濃淡，本來就是光影的效果 |

風險：
- 之前的 3D 試作你覺得像黏土人。這次的差別是：稜角分明的方塊、平塗不做圓滑的漸層、低解析度加描邊、頭身比例拉長。但還是要做出來給你看才算數。
- 需要手機的瀏覽器支援 3D 繪圖。近幾年的手機都可以。

配色先沿用現在的深藍和金色，剛好就是夜晚和燈光。

### 10.3 下一步

你確認方向後，我先做**一張風格定稿圖**：燈塔的診療廳、見習專師、一位求診的人、一隻霧獸、提燈的光。你覺得對了，才用它做整個遊戲。

## 11. 還要請你回答的三件事

1. **主訴清單。** 明年考試的範圍裡，內科、外科各有哪些主訴？第一版你想先做哪幾個？這個我不該用猜的。
2. **最後 3 分鐘實際要做什麼？** 只講診斷，還是也要講鑑別診斷、要開的檢查和處置？12 分鐘到的時候，考場是直接打斷嗎？我想讓試煉盡量照真的考站。另外，試煉裡病人要不要照樣掉血，還是只用沙漏當壓力？
3. **你說的「3D 像素」最接近哪一個？** A 方塊模型，像 Echo Generation、The Touryst（我的建議）；B 2D 像素角色放在 3D 場景，像 Octopath Traveler II；C 維持 2D 像素，只加強動態。
