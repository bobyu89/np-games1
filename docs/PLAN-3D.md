## 1. 結論

**3D 做得到，不需要退到「恐龍大戰外星人」。** 這次已經做出可以玩的 3D 試作（[`prototypes/sepsis-3d/`](../prototypes/sepsis-3d/README.md)）：斜視角六角棋盤、10 個公仔角色、4 種病灶敵人、ICU 場景、攻擊動畫和戰鬥回放，規則直接沿用灰盒版通過測試的那一套。

做法是：**Blender 用程式建模 → 匯出 GLB → 瀏覽器用 three.js 顯示**。整條管線都在這個 repo 裡，可以重跑。

### 做得到和做不到的

| | 項目 |
|---|---|
| ✅ 已做到 | 斜視角 3D 棋盤、公仔角色站在六角格上、待機動畫、出手動畫、飛行彈道、傷害數字、血條、羈絆面板、勝負結算 |
| ✅ 之後做得到 | 拖曳放置、音效、每個職類不同的出手動作、升星特效、鏡頭運鏡、教學關卡 |
| ❌ 做不到（需要美術人力） | 商業遊戲等級的角色模型、骨架動畫、過場動畫、語音 |

模型目前是「低多邊形公仔風」：大頭、浮空的手、手上拿的器材代表職類。這是程式能穩定產出的風格。想要更精緻，可以在 Blender 裡手修（見 §4）。

### 原創聲明

我們借的是自走棋這個**類型的慣例**（斜視角棋盤、羈絆面板、自動戰鬥）。角色、場景、介面、美術都是自己做的，不取自任何現有遊戲。這也是之後公開發表時比較安全的做法。

## 2. 為什麼不換成恐龍大戰外星人

1. **難的部分已經做完，而且跟主題無關。** 棋盤、鏡頭、動畫、戰鬥回放、模型管線都是通用的。
2. **恐龍不會比較好做。** 四隻腳、長尾巴的身體比公仔人形更難建模，也更難做動作。
3. **會失去教學和研究的目的。** Bundle 就是羈絆、黃金一小時、ISBAR 交班都綁在 ICU sepsis 這個主題上。

如果你想做恐龍大戰外星人當作**另一款純娛樂的遊戲**，它等於「換皮」：換一份遊戲資料（角色、羈絆、敵人）和一批模型，引擎不用重寫。要不要做由你決定（見 §7）。

## 3. 美術方向：夜班 ICU 立體模型

| 項目 | 決定 |
|---|---|
| 整體 | 深色的夜班 ICU，棋盤是床邊的一塊發亮區域 |
| 我方 | 公仔比例的醫療團隊，用**服裝顏色＋手持物**辨識：灰蓋檢體管（乳酸）、輸液袋、兩支血液培養瓶、針筒（抗生素）、輸液幫浦（升壓）、板夾＋聽診器（NP）… |
| 敵方 | 病理過程，不是病人：菌群（綠色刺球）、低血壓（指針掉到低處的血壓計）、乳酸堆積（紫色黏液，沒量測前是半透明的）、MODS（黑色核心，周圍繞著肺、腎、肝、心、腦） |
| 病人 | 躺在後方病床上。敵人每 60 分鐘朝病人攻擊一次，病人安全指數下降 |
| 棋盤 | 我方 8 格分前後排。前排青色（15–60 分鐘內出手）、後排沙色（超過 60 分鐘）：**顏色直接教「黃金一小時」** |
| 監視器 | 場景裡的生理監視器即時顯示 HR、MAP、Lactate 和病人安全指數 |
| 角色腳下的圓環 | 顏色代表職能羈絆（藍＝評估、橘＝處置、綠＝協調；NP 是藍綠各半） |

**需要臨床專家看的視覺隱喻**：低血壓畫成血壓計、乳酸畫成會長大的黏液、MODS 繞著器官。這些是我的設計，還沒有人審過會不會造成誤解。

## 4. 技術管線

```
tools/blender/build_models.py ──▶ prototypes/sepsis-3d/assets/models.glb ──▶ three.js r186
        （程序化建模）                    （1.2 MB、4.1 萬個三角面）              （瀏覽器）
                                                                                    ▲
                              rules/sim.js（規則，和灰盒版相同）─── 戰鬥結果與事件 ──┘
```

- **規則和畫面分開**：`sim.js` 算出整場戰鬥的事件清單，3D 舞台只負責照著播。所以 3D 版和灰盒版的勝負一定相同。
- **模型用程式產生**：改顏色、比例、加新角色都是改腳本再重跑，幾秒鐘完成。
- **可以手修**：腳本加 `--blend` 會另存 `.blend`。在 Blender 裡手修後，只要節點名稱不變就能直接替換（名稱規則見 [`tools/blender/README.md`](../tools/blender/README.md)）。測試會檢查名稱有沒有對上。
- **沒有建置步驟**：three.js 從 CDN 載入，原始檔就是上線的檔案。
- **技術選型變更**：GDD v0 寫的是 Phaser 4（2D 引擎）。改成 3D 後換成 **three.js r186**。

## 5. 現況（P0，這次完成）

| 項目 | 狀態 |
|---|---|
| 3D 佈陣：點角色、點格子，或按數字鍵 1–8 | ✅ |
| 3D 自動處置：依站位順序出手，時間軸 0–150 分鐘 | ✅ |
| Bundle 元素在實際執行的那一刻亮起，抗生素時間標在時間軸上 | ✅ |
| 結算：勝負、扣分、各元素執行時間、指引對照（附出處） | ✅ |
| 5 個回合都能玩，每回合有建議陣容 | ✅ |
| 手機直式和桌機寬螢幕版面 | ✅ |
| 商店、經濟、評估階段、院務事件、完整 ISBAR debrief | ❌ 只在灰盒版 |
| 研究紀錄 | ❌ 只在灰盒版 |
| 音效 | ❌ |

**驗證方式和限制**

- 自動測試 23 項全過：規則 17 項，加上 3D 版 6 項（模型和遊戲資料對得上、建議陣容每回合用 25 組隨機種子都控制得住、戰鬥事件帶有畫面需要的欄位）。
- 用無頭瀏覽器在手機尺寸（390×844）和桌機尺寸（1280×800、1440×900）實際操作：佈陣、開打、結算都沒有程式錯誤。
- **沒有在真的手機上測過。** 測試機沒有顯示卡，畫面是用 CPU 算的，所以量不到真實的流暢度。目前每個畫面約 120 次繪製呼叫、5.4 萬個三角面，以手機來說不算重，但要實機確認。

## 6. 分期

| 階段 | 內容 | 完成的定義 |
|---|---|---|
| **P0 視覺試作** | 這次 | ✅ 你看過畫面，決定要不要走 3D |
| **P1 完整流程搬進 3D** | 評估階段、商店與經濟、候補區、院務事件、完整 debrief、研究紀錄 | 3D 版能完整玩完第一章，研究紀錄格式和灰盒版相同 |
| **P2 手感** | 拖曳放置、音效、各職類專屬出手動作、第一回合教學引導 | 沒玩過的人不用解釋就能排出陣容 |
| **P3 美術** | 在 Blender 手修角色和場景；臨床專家審視覺隱喻 | 角色定稿，視覺隱喻通過審閱 |
| **P4 實測** | 真機效能測試、NP 學員試玩、IRB 送審準備 | 見 GDD §8、§9 |

灰盒版（2D）會保留：它是目前唯一有研究紀錄的版本，之後也可以當低階裝置的備用版。
